**1. Agent Skills for Software Development — jwilger/agent-skills ("factory pipeline")** — John Wilger, GitHub (v4.1)
`raw/articles/jwilger-agent-skills-event-modeling-factory-pipeline.md` — *filed, not yet ingested*
TLDR: A portable Agent-Skills repo whose `event-modeling` skill is the *upstream* step feeding a fully autonomous agent build pipeline: event model → GWT scenarios → vertical slices → autonomous TDD → review → mutation testing → CI. Event Modeling here is the human-authored spec that constrains and drives a *team* of coding agents (an "ensemble-team" workflow).
Why worth reading: This is the cleanest worked instance of your core thesis — EM as the spec that governs an agent factory — and it's the *opposite* direction from Dymitruk's "agents as users/processors" and Qlerify's "AI assists modeling". Distinct author/project from the already-ingested proophboard skill. This is the single highest-value un-compiled item in the KB right now.

**2. Extending Event Modeling: an optional "Query" (WHEN) on the read side** — Martin Dilger, LinkedIn (2026-06-29)
`raw/notes/dilger-extending-event-modeling-query-when.md` — *filed, not yet ingested*
TLDR: Dilger's first-ever deviation from the EM "standard" — after discussions at the Munich EM Conference, he proposes adding an optional read-side "Query (WHEN)" element that several independent people felt was missing. Why worth reading: A rare change to the EM *method itself*, from the person closest to the standard — and a direct artifact of the Munich conference you've been tracking. Matters for how the method evolves under agent-driven codegen.

**3. My Wife Asked Me to Build a Registration Form for a Flea Market** — Martin Dilger, LinkedIn (2026-07-01)
`raw/notes/dilger-flea-market-model-code-deploy-30min.md` — *filed, not yet ingested*

Why worth reading: Concrete evidence for the "EM is a communication tool legible to non-engineers" claim and the model→generated-code on-ramp (pairs with [[dilger-build-kits-model-to-generated-code]]). Short, illustrative, on-thread.

**4. Are you using Draw.io for Event Modeling? (model-in-code, AI manipulation, MCP guardrails)** — Martin Dilger, LinkedIn (2026-06-30)
`raw/notes/dilger-drawio-event-modeling-model-in-code.md` — *filed, not yet ingested*
TLDR: Dilger agrees the model belongs *in the repo* (clients already have AI directly manipulate draw.io XML) but argues raw draw.io fails the agent case: the XML isn't human-readable, AI has "no framework, no rules" so it drifts, and non-technicians can't contribute — motivating a structured, MCP-guardrailed model format instead.
Why worth reading: Sharpens the "model-in-code + guardrails for the agent" argument that underpins EmLang/ESDM and the Triplet — the *why raw diagrams aren't enough for agents* case, in one page.
