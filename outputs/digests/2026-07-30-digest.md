**1. Adaptech Group — Your Workflow Should Not Live Inside a Giant Process Manager** (Dymitruk / Adaptech, LinkedIn Pulse, 2026-07-28) — *new wiki page*
[[adaptech-workflow-not-inside-giant-process-manager]] · concept [[process-managers-and-todo-lists]]
- **TLDR:** Don't coordinate a long-running workflow with one big saga/process-manager that hides its state in branches and in-memory flags. Instead: (a) build a **projected to-do list** — a CQRS read model that records, per active process, what's known / done / unfinished / ready-to-continue (worked stock-purchase example: stock+qty, price received?, price timestamp, submitted?, result, retry allowed?) — which turns the event log into a view people *and* automated processors read; and (b) run many **focused single-responsibility processors** that each watch that list and react only to their fields (fetch-price / submit / retry-or-verify). Supporting claims: external calls are business *states* (not-sent / awaiting / too-late / done-unconfirmed → need timestamps + idempotency keys); recovery should be visible *before* failure (verify-don't-recharge); business-language statuses (`PaymentAcceptedAwaitingShipment` > "instance at step 7") power dashboards/support/SLA.
- **Why it's worth reading:** This is the dedicated primary for Event Modeling's **Automation pattern** and the podcast's "sagas → to-do lists" theme — the one substrate piece that shows, concretely, how EM's projections+automations replace a process manager. Directly on your EM/ES focus, and it's the only genuinely new page since the last digest.
