## Read next

**1. Martin Dilger — "Planning like it's Excel: clear structure makes a spec legible to a human and an AI at once"** (LinkedIn, 2026-07-09) · `raw/notes/dilger-planning-like-excel-legible-to-human-and-ai.md` · *filed, not yet ingested*

- **TLDR:** Whiteboards give too much freedom — people invent patterns mid-session and six months later nobody can read the board; Event Models degrade the same way without an owner. So eventmodelers.ai enforces an **Excel-like left-to-right grid** that (a) forces a plot/storyboard you can't wander off, and (b) gives every element a **cell-reference coordinate**. That coordinate is the payoff for agents: *"I can tell an AI 'add a field in B3, adjust all dependents' and it means something precise. It talks back the same way — 'there's a problem in B3, adding items might be missing the price.'"* Thesis: clear structure is what makes one spec legible to a human and an AI at once. Teases a video series on agentic event modeling (Getting started / Agentic Modeling / Git version control / Spec-Driven-Building / On-Prem / Sketching / the timeline idea).
- **Why it's worth reading:** Your tightest focus — EM×agents. It's a concrete mechanism for the *model-as-agent-legible-spec* idea in [[event-modeled-agent-design]]: coordinate-addressability turns the event model into an API the agent can both read and edit precisely.

**2. Anthropic (Claude Code team) — "Getting started with loops"** (claude.com/blog, 2026-06-30, de Oliveira & Segner) · `raw/articles/anthropic-getting-started-with-loops.md` · *filed, not yet ingested*

- **TLDR:** The vendor's own loop taxonomy. Defines **loops = agents repeating cycles of work until a stop condition is met**, classified by trigger / stop-criteria / primitive / task-fit into four types: **Turn-based** (user prompt; encode verification as a SKILL.md), **Goal-based** (`/goal` — an evaluator model re-checks a deterministic success criterion plus a turn cap, "stop after 5 tries"), **Time-based** (`/loop` local, `/schedule` cloud), and **Proactive** (event/schedule, no human — compose `/schedule` + `/goal` + skills + dynamic workflows + auto mode). Plus quality guidance (clean codebase, self-verify via skills, reviewer agent with fresh context = maker≠checker) and token governance (`/usage`, pilot before large runs, scripts for deterministic work).
- **Why it's worth reading:** Maps almost one-to-one onto LangChain's four stacked loops ([[langchain-the-art-of-loop-engineering]]) and fills the vendor-primary slot next to Osmani/swyx. It also grounds the abstract loop discourse in concrete primitives — useful if you want the KB's [[loop-engineering]] page to name mechanisms, not just concepts.

**3. Adam Tornhill — "Why Human-Level AI Won't Be Enough"** (Code for Humans and Machines, Substack, 2026-06-30) · `raw/articles/tornhill-why-human-level-ai-wont-be-enough.md` · *filed, not yet ingested*

- **TLDR:** Even coding agents at today's best-human-expert level won't be enough, because **AI raises its own quality bar** through two forces: **scale** (Lehman's laws — useful software keeps growing more complex; defect opportunities scale with code and change volume) and **speed** (orders-of-magnitude faster generation → higher churn/fault risk = "wrong at scale"). LLMs' stochastic core means a one-in-a-million error recurs once you make millions of decisions. He rejects the "superhuman code quality" path (no training data/feedback signal; AGI perennially "a few years away") and prescribes the opposite: don't chase perfect code — **"double down on creating environments where unreliable agents reliably produce acceptable outcomes."**
- **Why it's worth reading:** The sharpest statement yet of the KB's *environment-over-model* through-line — it puts a theoretical floor under harness/loop engineering and the code-health thread ([[tornhill-codescene-unhealthy-code-agentic-token-cost]], [[borg-tornhill-code-for-machines-not-just-humans]]), and echoes Dilger's "harness is 20%, requirements are 80%."

**4. Simon Willison — "Rewriting Bun in Rust"** (Simon Willison's Weblog, link-blog, 2026-07-08) · `raw/articles/willison-rewriting-bun-in-rust.md` · *filed, not yet ingested*

- **TLDR:** Willison's commentary on Jarred Sumner's post about the agentic Zig→Rust rewrite of Bun — a real-world stacked-loop case study. The enabling trick: Bun's **TypeScript test suite (~1M assertions) acted as a language-independent conformance suite** = the grader/verification loop. Sumner "monitored workflows… prompting Claude to edit the loop to fix things" (loop-editing) and, when something broke, **"fixed the process that generates the code instead of hand-fixing the code"** (the hill-climbing/trace loop). Reviewing a +1M-line LLM-authored PR is the comprehension-debt angle; coordinated parallel agents ran in worktrees; cost ≈ $165k (5.9B uncached input / 690M output / 72B cached-read tokens). Shipped in Claude Code v2.1.181 — "Boring is good."
- **Why it's worth reading:** A concrete, high-stakes instance of the verification-loop + hill-climbing model that the theory sources (LangChain, Osmani, the Anthropic guide above) describe abstractly — good ballast for [[loop-engineering]] and the maker≠checker seam.
