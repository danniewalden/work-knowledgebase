**2. Dilger — "How I use Local-LLMs to build software systems" (2-part)** · `raw/notes/dilger-local-llm-distributed-agent-setup-event-modeling.md` · *filed, not yet ingested*
- **TLDR:** The most concrete implementation report yet of Dilger's always-on Event Modeling agent factory. 6–10 agents run in 24/7 ralph-loops across 3 Asus GX10 boxes (no clustering), harnessed by Claude Code / OpenCode over Ollama running Gemma4 (~60 tok/s) and Qwen3.6:27B (~30 tok/s). Workflow: model a slice with stakeholders → set "Planned" → one agent claims it and flips it "In Progress" (a single-writer lock; other agents skip it) → builds it. Change a slice by moving it "Done"→"Planned" and an agent diffs spec-vs-code and adjusts. "At some point you stop thinking about the code" — attention moves entirely to the spec. Calls EM + Event Sourcing + slice-based architecture "the triplet of flexible architectures."
- **Why it's worth reading:** This is your Event-Modeling-Agent-Harness idea running on real, cheap, local hardware — the operational "how" (models, throughput, the claim/lock mechanism) that the earlier conceptual posts left abstract.

**3. Osmani — "Own the Outer Loop"** · `raw/articles/addyosmani-own-the-outer-loop.md` · *filed 07-12, not yet ingested (freshest)*
- **TLDR:** Osmani's follow-on to his loop-engineering primary. As agents take the *inner* execution loop (investigate→implement→verify→repeat), engineers must own the *outer* loop — accountability — via three terms: **Quality** (back-pressure checks that emit evidence), **Verdict** (the human ship/block/redirect decision), **Answerability** (guaranteeing you can explain *why*). Humans belong in the constraints / sampling / audit / ownership loops, *not* the inner loop; a "factory" is loops at scale. Backed by fresh data: Sonar 2026 (42% of committed code AI-assisted), GitLab Jun-2026 (governance happens *after* creation — the review/validation bottleneck), an Anthropic RCT (AI-assisted engineers score 17pp lower on comprehension), Wharton (people accept wrong AI ~75% of the time, with *more* confidence). "The agent can ship more than you can review."
- **Why it's worth reading:** It's the only genuinely new input this cycle and it sharpens the "stay the engineer" thread into a concrete accountability contract — the human-boundary counterpart to Dilger's autonomous factory in item 2.

**4. Dilger — "Extending Event Modeling: an optional 'Query' (WHEN) on the read side"** · `raw/notes/dilger-extending-event-modeling-query-when.md` · *filed, not yet ingested*
- **TLDR:** Notable because Dilger — who has been scrupulous about sticking to Dymitruk's EM "standard" — extends the notation *for the first time*. After discussions at the Munich conference (independently raised, and pre-discussed with Dymitruk), he adds an **optional WHEN ("Query") clause on the read side** so GWT scenarios can express complex queries, not just the usual GIVEN…THEN for read models. He frames it cautiously and is explicitly seeking community feedback.
- **Why it's worth reading:** A rare method-level change to Event Modeling from a core practitioner, straight out of the 2026 conference — worth knowing before it propagates into tooling and GWT-generation you might rely on.

**5. Dilger — "Are you using Draw.io for Event Modeling?" (model-in-code, MCP guardrails)** · `raw/notes/dilger-drawio-event-modeling-model-in-code.md` · *filed, not yet ingested*
- **TLDR:** Dilger endorses "the model belongs in the repo" but catalogues why raw draw.io XML is a poor substrate for agents (unreadable diff, no rules/framework so AI mis-edits, collaboration friction). His alternative pipeline: export the model to a standardized JSON, version it in git, let a local agent manipulate the JSON via provided **skills**, and use an **MCP endpoint to validate changes before commit** so the agent gets guardrails and self-corrects — then visualize the JSON in the platform viewer and feed it to code-gen "Build Kits" (Node/Java/Kotlin).
- **Why it's worth reading:** A clean statement of the model-in-code + MCP-guardrail pattern that recurs across your EM×agents sources (Fraktalio, proophboard, jwilger) — the "how do you keep an agent honest against the model" mechanism.
