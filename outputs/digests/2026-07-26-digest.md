**1. Software Factories, Light and Dark — Addy Osmani (addyosmani.com, Jul-20)**
`raw/articles/addyosmani-software-factories-light-and-dark.md` — *filed 07-23, not yet ingested*
TLDR: Osmani's most complete statement of the loop→harness→factory stack: a *loop* is one agent doing one job on repeat, a *harness* is the walls around it (sandbox, tools, memory, done-gates), and a *factory* is "an org chart made of loops" draining through one review gate. A **dark factory** ships code no human reads (verified only by machines, the FANUC/Xiaomi lights-out analogy — "in software, the floor is the diff"); it doesn't pay down *comprehension debt*, it takes it on "with the tests green the whole way." The fix is a **lit factory** that moves human judgment *upstream* to product/design/architecture, governed by **back pressure**: hand a loop only as much autonomy as you can cheaply and reliably verify. Leans on Dex Horthy/HumanLayer's AIEWF talk "Harness Engineering Is Not Enough," and — answering the "graph engineering" thread flagged 07-20 — argues owning your control flow is "walking the graph back around the loop" (LangGraph/LlamaIndex/state machines).
Why it's worth reading: this is the current apex of the loop-engineering thread you track — it adds the *factory* rung on top of [[loop-engineering]], gives you the light/dark + back-pressure vocabulary for deciding what to automate, and ties graphs-vs-loops straight into [[nick-tune-graphs-memory-skills-agents]]. The single highest-leverage read of the three.

**2. Earning taste and judgment — Addy Osmani (addyosmani.com, Jul-14)**
`raw/articles/addyosmani-earning-taste-and-judgment.md` — *filed 07-21, not yet ingested*
TLDR: The companion piece: taste used to be a byproduct of "the reps," agents took the reps, so juniors now have to acquire judgment *on purpose*. Marshals labour-market data (recent-grad underemployment, AI-exposed 22–25 employment decline, the Microsoft "sleep() to hide a race condition" cautionary tale) to argue the entry-level rung is thinning while judgment-heavy senior roles grow. Restates the inner-loop (agent: investigate/implement/test/report) vs outer-loop (human: worth-attention? verify by evidence → approve/block → carry the consequence) boundary from "Own the Outer Loop," names the "two debts" (cognitive surrender + comprehension), and gives seven concrete habits — read more code than you generate, keep a "wrong log," specify and verify separately, **build an eval/rubric and run it on 50 real AI PRs**, calibrate autonomy per task.
Why it's worth reading: it's the human-capital / "stay the engineer" side of the same argument — the eval-as-personal-calibration and specify-vs-verify habits are directly actionable, and it strengthens the accountability seam already in [[addyosmani-own-the-outer-loop]], [[willison-understand-to-participate]], and [[loop-engineering]].

**3. A Fireside Chat with Cat and Thariq from the Claude Code team — Simon Willison (simonwillison.net, Jul-21)**
`raw/articles/willison-fireside-chat-claude-code-team.md` — *filed 07-25, not yet ingested (freshest, since cutoff)*
TLDR: Willison's edited+annotated transcript of his AIEWF fireside with two Anthropic Claude Code PMs. Concrete vendor-practice data points: **Claude Tag (Slack) now lands 65% of the team's product-eng PRs**; humans are being removed from code review for "outer-layer" changes through 6+ months of building trust (incident PRs get added to an *eval set* so review never regresses); the Claude Code **system prompt shrank ~80%** because frontier models (Fable 5, Opus 4.8) do *worse* with examples and "don't do X" lists — "soften the prompt," give context not constraints, one system prompt per model; auto mode runs a Sonnet classifier over every tool call and gates the sandbox; **Claude Tag memory = "a markdown file per channel."**
Why it's worth reading: it's a rare look at how a top team actually runs coding agents at scale — the maker≠checker/eval-set discipline, the prompting-inversion, and the on-disk-memory primitive all corroborate your harness/loop-engineering pages from the vendor side. Caveat: it's an interview transcript, not a Willison long-form argument, so it's evidence-rich but lighter on thesis.
