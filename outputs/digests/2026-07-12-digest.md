1. **Dilger — "Planning like it's Excel" (spec legible to human & AI)** — `[[dilger-planning-like-excel-legible-to-human-and-ai]]` · *new wiki page (also raw note)*
   **TLDR:** Freeform whiteboards give too much freedom — people invent patterns mid-session and the board is unreadable six months later — so eventmodelers.ai replaces the canvas with an **Excel-like left-to-right grid** that enforces the storyboard *and* gives every element a **cell-reference coordinate**. You can then tell an agent *"add a field in B3, adjust all dependents"* and it means something precise; the agent talks back the same way (*"there's a problem in B3…"*). Thesis: clear structure makes one spec **legible to a human and an AI at once.** Teases a coming agentic-event-modeling video series.
   **Why:** Straight down the EM×agents focus line — the concrete mechanism for making an Event Model an agent-addressable spec, not just a diagram.

2. **Anthropic (Claude Code team) — "Getting started with loops"** — `[[anthropic-getting-started-with-loops]]` · *new wiki page*
   **TLDR:** The **vendor-canonical loop taxonomy**: "loops = agents repeating cycles of work until a stop condition is met," classified by trigger / stop-criteria / primitive / task-fit into four types — **Turn-based** (encode verification as SKILL.md), **Goal-based** (`/goal` + evaluator + turn cap), **Time-based** (`/loop` local, `/schedule` cloud), and **Proactive** (event/schedule, no human). Maps 1:1 onto LangChain's four stacked loops, plus notes on quality (reviewer agent, self-verify) and token governance (`/usage`, pilot runs).
   **Why:** The missing vendor primary that completes the Osmani / LangChain / swyx loop-engineering set — canonical for the pattern, and the primitives map directly onto how *this* KB's own scheduled/always-on runs are built.

5. **Tornhill — "Why Human-Level AI Won't Be Enough"** — `[[tornhill-why-human-level-ai-wont-be-enough]]` · *new wiki page*
   **TLDR:** Even human-expert-level coding agents won't suffice, because AI **raises its own quality bar**: via **scale** (bigger systems, Lehman's laws — defects grow with code+change volume) and **speed** (orders-of-magnitude faster generation → higher churn, "wrong at scale"), and a stochastic core means a one-in-a-million error recurs across millions of decisions. Rejects the "superhuman code quality" path (no training/feedback signal). Prescription: don't chase perfect code — **"create environments where unreliable agents reliably produce acceptable outcomes."**
   **Why:** The sharpest statement yet of the KB's **environment-over-model** through-line; puts a *why* under harness/loop engineering and converges with Dilger's "harness is 20%, requirements are 80%."

6. **Willison — "Rewriting Bun in Rust" (agentic case study)** — `[[willison-rewriting-bun-in-rust]]` · *new wiki page*
   **TLDR:** Commentary on the Bun Zig→Rust rewrite as a real stacked-loop case: a **~1M-assertion TypeScript test suite** acts as a **language-independent conformance/grader suite**; "monitored workflows… prompting Claude to edit the loop" = loop-editing; **"fix the process, not the code"** = the hill-climbing/trace loop; reviewing a **+1M-line** LLM-authored PR raises the verification-burden angle; token economics ≈ **$165k**.
   **Why:** The most concrete grounding in the KB for the verification + hill-climbing loops — a shipped, real-world instance of loop-engineering's top two loops.
