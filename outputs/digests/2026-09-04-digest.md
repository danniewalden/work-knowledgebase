### 1. Event Modeling Podcast, Ep 47 — "Agentic Modeling, Audit Trails, and the Fish Shell Effect" (Martin Dilger & Adam Dymitruk)
`raw/articles/dilger-podcast-episode-47-agentic-modeling-audit-trails.md` — *filed, not yet ingested*

**TLDR.** Dilger ran a Claude Code instance and a Hermes agent modeling *simultaneously alongside him* on a
live event model — adding slices and comments — and says it was indistinguishable from modeling with humans.
He also unveils a **"what do you think" skill** that points an agent at an event model and has it post
clarifying-question comments on slices ("what happens if the user clicks *clear cart* twice?"). The tuning
lesson is the substantive bit: v1 flooded the model with ~100 comments inventing hypothetical gaps;
restricting the agent to comment **only on what is actually present**, without inventing scenarios, made it
dramatically more useful. Dymitruk's counterpoint runs the other way — agents need an **audit trail, not a
snapshot**: "Events are the truth… If an agent goes sideways, follow the event trail, find the divergence,
fix it, replay." He also warns an over-eager agent can bloat a given-when-then list until a simple slice
*looks* complex, which matters because event modeling is visual.

**Why it's worth reading.** This is the only genuinely on-thread Event Modeling × agents item to arrive in
weeks, and it is the closest thing yet to the KB's long-open gap — an agent participating *in* the model
rather than consuming one. *Caveats to carry forward: **vendor self-report** throughout (eventmodelers.ai is
Dilger's own commercial platform), the "indistinguishable from humans" claim is an **impression, not a
measurement**, and the page is **undated** — treat the date as unresolved.*

### 2. "Maybe We Shouldn't Be Reviewing All This Code" — Rachel Laycock, martinfowler.com (2026-09-02)
`raw/articles/laycock-maybe-we-shouldnt-be-reviewing-all-this-code.md` — *filed, not yet ingested*

**TLDR.** A direct response to Brian Houck (DX), written out of a panel disagreement. Her position: the
problem is not that AI broke code review, it is that we were using code review to solve the wrong problems.
Do **not** automate review to keep pace with agent output — instead move each thing review is actually for
to where it belongs and earlier: knowledge transfer → pairing; junior learning → working alongside seniors;
collective ownership → team structure and mobbing; architectural alignment → design sessions **plus
constraints encoded as fitness functions**; formatting/lint/security → automate. Then review by exception.
She closes on "We need engineers to understand systems, not diffs."

**Why it's worth reading.** It supplies the organisational answer to the verification-burden strand and wires
**fitness functions** directly into the governance rung of the flagged-important business-capabilities ladder
— and it lands the same week as, and in direct opposition to, Brewster's capitulation below. *Caveats:
**not independent** (Thoughtworks CTO on the Thoughtworks-hosted site, the same house that coined harness
engineering); the two figures she relays — Meta's +106% LOC per human-landed diff, +64% median PR size —
reach her **via Houck at DX, a vendor selling productivity measurement**, i.e. secondhand vendor numbers;
and her "ten times the code" is rhetorical, not measured.*

### 4. "An Accidental Blackboard" — Giles Edwards-Alexander, martinfowler.com "Exploring Gen AI" (2026-09-02)
`raw/articles/edwards-alexander-an-accidental-blackboard.md` — *filed, not yet ingested*

**TLDR.** Thoughtworks put 10 engineers in one Barcelona room for four days of "hyper-agentic" work building
an airline IROps system, and accidentally reproduced the **blackboard system** (Hearsay-II, 1980; Gelernter's
tuple spaces, 1986). A commit-and-rebase-continuously discipline, combined with in-repo plans keyed to
numbered spec sections, meant agents began *reading each other's plan lines*: marking work in progress,
self-excluding from claimed lines, and receiving implementation notes on completion. They then exploited it
deliberately — directing one agent to watch the repo and integrate the cost model when it landed. The honest
part is the ending: he identified the single prompt that started the cascade but is "not convinced I would be
able to reliably prompt our agents into doing it again", and the frequent-push discipline that *created* the
channel had to be backed off because it overloaded CI — which killed the effect. He now wants the channel to
live independently of source control (project "Talwrn").

**Why it's worth reading.** An append-only shared log that autonomous workers read and write, where the
history rather than the snapshot is the coordination medium, is the event-sourcing substrate arriving from
the opposite direction — and it lands the same week as Dymitruk's "audit trail, not a snapshot". *Caveat:
**not independent** — Thoughtworks author on Thoughtworks' own channel, the same house as items 2 and 5.*

### 5. "GPT-6 Astra" — Simon Willison (2026-09-03)
`raw/articles/willison-gpt6-astra.md` — *filed, not yet ingested*

**TLDR.** Launch blogmark, and one number in it is worth more than the rest of the release: Astra scores
**99.9% on ARC-AGI-3 using OpenAI's custom "Provider Adapter harness" for $19K, versus 62.7% on the default
ARC-AGI harness for $26K** — the adapter preserving opaque reasoning state between requests and compacting
long conversations so the model reuses prior work. Same model, same benchmark, 37 points of spread and a
*lower* cost, purely from the harness. Willison also notes Artificial Analysis still has Fable 5.1 ahead on
raw intelligence while Astra leads their coding-agent cost-efficiency frontier.

**Why it's worth reading.** It is the cleanest harness-not-model datum the KB has, and it arrives from a
model launch rather than from a harness advocate — useful precisely because it is not the harness-engineering
camp arguing its own case. *Caveats: **OpenAI's own self-reported benchmark**; swyx's companion piece
(`raw/articles/swyx-gpt6-astra-automated-ai-engineer.md`) is an **unfinished draft** with a stated
early-access conflict, so treat it as impression, not measurement.*

### 6. "PRs NOT Welcome: How Top AI Open Source Projects Are Managing Thousands of Contributors" — Richard MacManus, Latent.Space (2026-09-01)
`raw/articles/macmanus-prs-not-welcome-software-factories.md` — *filed, not yet ingested*

**TLDR.** Vercel's AI SDK, Astro, Flue and tldraw are closing external PRs and replacing them with
maintainer-owned **software factories** — a team of agents that triages, reproduces the bug, implements,
reviews, and hands back to a human to merge. Vercel's AI SDK had 1,000+ open issues and ~800 PRs by late June.
Grammel's stated reason is not throughput but **provenance**: "we develop trust in that particular agent
configuration" from track record on a bug category, versus not trusting community-run agents at all.

**Why it's worth reading.** It reframes maker≠checker as a *provenance* argument rather than a role argument,
and it is the governance rung being enforced by policy rather than by build constraints — the third mechanism
alongside Tune's fitness functions and Laycock's team design. *Caveats: **vendor self-report** on the headline
(Vercel's own unaudited "25–35% of merged PRs, 70–80% of issues closed", four weeks in), and Schott's
"totally shifted in six months" is an **impression, not a measurement**.*
