## Read next

**1. Dilger — "We need the model in the code": draw.io, AI manipulation, MCP guardrails** — Martin Dilger, LinkedIn 2026-06-30
*Path:* `raw/notes/dilger-drawio-event-modeling-model-in-code.md` — **filed, not yet ingested**
**TLDR:** Dilger endorses keeping the event model *in the repo* and having AI manipulate it directly, but argues raw draw.io XML has no rules for the agent to follow (easy mistakes), isn't human-readable, and hurts collaboration. His recommended flow: edit → export to a standardized JSON → version in git → a local agent manipulates the JSON via provided skills → the **MCP validates each change before commit** so the agent gets guardrails and self-corrects → visualize in the platform's Model-Viewer → generate code via Build-Kits (Node/Java/Kotlin).
**Why it's worth reading:** This is the most concrete "model-in-code + agent + MCP-as-guardrail" workflow Dilger has posted — squarely on the EM×agents focus and directly extends `dilger-event-modeling-agent-harness` and the EmLang/model-as-source-of-truth thread.

**2. Dilger — First-ever extension of the Event Modeling "standard": an optional "Query" WHEN** — Martin Dilger, LinkedIn 2026-06-29
*Path:* `raw/notes/dilger-extending-event-modeling-query-when.md` — **filed, not yet ingested**
**TLDR:** Dilger, who says he'd deliberately never deviated from Dymitruk's EM standard, is adding one element: an *optional* `WHEN` ("Query") on the **read side** of Given-When-Then, so read-model scenarios can express complex queries (GIVEN a user was registered / WHEN we query by email / THEN the user is returned). It came out of repeated independent requests at the Munich EM Conference (and a prior Dymitruk conversation); he frames it as feedback-driven, not unilateral.
**Why it's worth reading:** A rare change to the EM notation itself, touching `given-when-then` — the acceptance-gate seam for agent-built slices. Worth knowing before it propagates into tooling and the online course.

**5. Fowler — Agentic Programming (the vendor-neutral definition)** — Martin Fowler, martinfowler.com 2026-05-21
*Path:* `[[fowler-agentic-programming]]` — **new wiki page (just ingested)**
**TLDR:** Fowler's bliki fixes the canonical definition the KB had been citing loosely: agentic programming = **prompt-then-review**, distinct from *vibe coding* (humans don't review the code) and from autocomplete. **Why it's worth reading:** It's the neutral anchor under Thread 4 — a non-vendor authority to cite when the harness/loop discourse gets marketing-heavy, and it cleanly separates agentic programming from vibe coding (feeding `vibe-modeling`).
