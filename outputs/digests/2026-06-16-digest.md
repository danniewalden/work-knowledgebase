## Read next

**1. Borg, Tornhill et al. — "Code for Machines, Not Just Humans: Quantifying AI-Friendliness with Code Health Metrics"** (arXiv 2601.02200, FORGE 2026)
`raw/papers/borg-tornhill-code-for-machines-not-just-humans.md` — **filed, not yet ingested** (freshest unprocessed input).
*TLDR:* A peer-reviewed study (5,000 Python files, six LLMs incl. Claude) testing whether code that's healthy for humans is also easier for AI to refactor without breaking behavior. Answer: yes — LLMs have 15–30% lower break rates on "Healthy" code (CodeHealth ≥9), and CodeHealth predicts refactoring success better than perplexity or lines-of-code. Proposes using CodeHealth to route work: low-CH files need human oversight, high-CH files are safe for agents.
*Why read it:* This is the independent, peer-reviewed grounding for the code-health × harness thread you've only had via Tornhill's LinkedIn reshare — it turns "unhealthy code costs agents more" from a vendor claim into a measured result, and gives a concrete sensor (CodeHealth) for `harness-engineering` / `fitness-functions`.

`[[fritzsche-functional-core-imperative-shell-agentic-coding]]` — **new source page.**

*Why read it:* It's the concrete repo recipe that operationalizes `locality-of-reference` and Miller's "codebase is the prompt," and ties VSA, agent-legibility and business-capability ownership into one buildable pattern — squarely on your EM×agents + substrate focus.
