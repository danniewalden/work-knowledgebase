## Read next

1. **Dilger — "The Triplet: a flexible, agent-enabled architecture"** (Martin Dilger, LinkedIn newsletter, 2026-07-26) — `[[dilger-triplet-flexible-agent-enabled-architecture]]` — *new wiki page.*
   **TLDR:** The definitive naming of the KB's focus thesis: Event Modeling (the plan) + Vertical Slices (the structure) + Event Sourcing (the store), used *in union*, as one architecture. The argument's hinge is coupling — the same low coupling that makes the system cheap for humans to change makes it cheap for an *agent*: an agent works a single slice and needs only that slice's context + event log + model, so adding agents makes delivery faster, not slower. Requirements are treated as *part of* the architecture (model-first), and he floats "Slice-Cycle-Time" as a story-point replacement. eventmodelers.ai is built around it.
   **Why:** This is the packaged operating model for your entire EM×agents focus — the one page that ties plan/structure/store into a single agent-enabled whole. (Caveat: vendor/self-reported.)

2. **AHE — "Agentic Harness Engineering"** (Lin et al., Fudan/Peking, arXiv:2604.25850) — `[[ahe-agentic-harness-engineering]]` — *new wiki page.*
   **TLDR:** The peer-review-grade primary the loop-engineering thread had been missing. An *evolution agent* autonomously rewrites a coding agent's harness (the base model kept **frozen**) using three observability pillars — component (a decoupled 7-file substrate, each failure → one file → git-rollback), experience (millions of trajectory tokens distilled to per-task root-cause), and decision (a falsifiable change-manifest pairing each edit with predicted fixes + regressions). Result: Terminal-Bench 2 pass@1 **69.7 → 77.0%** over 10 iterations, beating the hand-built Codex-CLI harness — and the gain is **structural, not prose** (memory +5.6 / tools +3.3 / middleware +2.2 pp; system-prompt-only *−2.3* pp). The frozen harness transfers cross-model, largest on weaker bases. Honest failure mode: "regression blindness."
   **Why:** Turns "hill-climbing loop" and "engineer the environment, not the model" from vendor slogans into a controlled experiment — the empirical anchor under loop-engineering and Tornhill's environment-over-model thesis.

3. **Osmani — "Software Factories, Light and Dark"** (Addy Osmani, 2026-07-20) — `[[addyosmani-software-factories-light-and-dark]]` — *new wiki page.*
   **TLDR:** Defines the top rung of the stack: loop → harness → **factory** ("an org chart made of loops," not a bigger agent). A *dark* factory ships code no human has read (verified only by machines, taking on **comprehension debt** with the tests green the whole way); a *lit* factory keeps human judgment where a wrong answer is expensive and moves review upstream. Back-pressure is the discipline — "hand a loop as much autonomy as you can cheaply and reliably verify, and not one inch more" — because verification, not generation, is the constraint. Closes with loops-vs-graphs ("walking the graph back around the loop").
   **Why:** The narrative field-report companion to the measured AHE paper, and it answers the "graph engineering vs loop engineering" framing your watch has flagged repeatedly. (Caveat: opinion, synthesizes Dex Horthy's talk.)
