# Tornhill/CodeScene — What Unhealthy Code Costs in the Agentic Era

LinkedIn reshare by **[[adam-tornhill]]** (CodeScene founder) of a CodeScene post (Markus Borg / Asko
Nõmm) promoting a 2026-06-26 webinar. Filed 2026-06-14. A vendor webinar promo, but it carries a
concrete (claim-level) research finding worth tracking. Raw:
`raw/articles/tornhill-codescene-unhealthy-code-agentic-token-cost.md`.

## Key claims (CodeScene research, per the post)

- **Agents perform worst where they're needed most** — in the highest-technical-debt parts of legacy
  codebases. "Most industrial codebases are not ready for the agentic era."
- **Unhealthy code increases agent token spend by 35–45%** across Java, C++, and Python ("what if
  35–45% of your agent token spend is wasted?").
- Implied remedy: keep generated code healthy *from the start* via an agentic workflow + code-health
  sensors (CodeScene's pitch).

## Why it matters

A quantified bridge between **code health / technical debt** and **agent economics + reliability** —
i.e. code health as a first-class concern of [[harness-engineering]] and a driver of
[[agentic-coding]] quality risk. It complements [[fowler-bockeler-maintainability-sensors]]
(maintainability *sensors* keep AI-generated code in check) by adding a cost argument: bad code
doesn't just risk defects, it inflates token spend and degrades agent performance. Sits adjacent to
the [[event-modeled-agent-design]] thesis that a clean, legible structure makes agents more effective.

## Caveats

Webinar promo; the underlying research (Markus Borg) is presented at the session, so the 35–45% figure
is **claim-level / not independently verified** here. Vendor-motivated (CodeScene sells code-health
tooling). Capture the actual research paper/recording if it surfaces.
