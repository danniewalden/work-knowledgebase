# Source: Fritzsche — "The entire .NET scene has been stuck somewhere in the mid-2000s"

LinkedIn post by **[[rico-fritzsche]]**, 2026-09-03. Raw capture:
`raw/notes/fritzsche-dotnet-scene-stuck-in-mid-2000s.md`. **Deliberately short page. Per its capture
note: OPINION / community critique, not measurement. The .NET-community complaint is off-thread; one claim
inside it is on-thread and is stated better in his next-day post.**

## Summary

A community complaint: LinkedIn's .NET discourse *"revolves around trivial implementation tips — the kind
that Claude Code or Codex can answer in milliseconds"* and *"these optimization tips don't matter for most
applications anyway, because the product is still light-years away from needing to scale."* Off-thread,
and not further summarized here.

## Key points — the one on-thread claim

> "Writing code is tedious work. And as a passionate programmer with over 30 years of experience, I don't
> want to downplay that. But programming isn't the most important thing — or rather, **writing code isn't
> crucial for creating a usable application with business value**. In the future, we won't need pure
> programmers who just type code anymore. And **I think it's great that this bottleneck is
> disappearing**."

With the same substitution his next-day post develops: *"What will matter most is engineering knowledge:
How do I design and build a system? How do I handle dependencies? How is the code organized so that I can
expand the system without risks? Which patterns are appropriate?"* and *"It will no longer be about a
specific programming language, but about choosing the right one for the problem at hand."*

Two things distinguish it from the sibling post: the explicit **"bottleneck"** framing (code production as
a constraint whose removal he welcomes), and the concession that writing code *is* real work he is not
dismissing.

## Limits

- **Opinion, no evidence, no examples.** A polemic, written partly to needle a community — including a
  jab at AI-generated LinkedIn posts, which is worth noting given the post's own genre.
- **The "bottleneck disappearing" claim is asserted, not shown**, and sits oddly with everything else in
  this batch: [[miller-pondering-continuous-integration-ai-world-order]] describes *verification*
  capacity becoming the new bottleneck under exactly the conditions Fritzsche celebrates. If code
  production stops being the constraint, something else becomes it; he does not ask what.
- His characterization of a whole community from its LinkedIn feed is a sampling argument he does not
  defend.
