# Index

The catalog of every page in the wiki. The LLM updates this on every ingest and
reads it first when answering a query. Each entry: link + one-line summary.

**Scale, as of the 2026-09-04 ingest: 251 source pages, 85 concepts, 84 entities.** That ingest was the
largest to date — roughly 90 sources — and it moved the KB's centre of gravity in four ways worth knowing
before drilling in. (1) **Harness evolution became a research field with a live dispute**: ten arXiv
papers are now catalogued, **every one of them a preprint and none peer-reviewed**, and the headline gains
(AHE's Terminal-Bench 69.7→77.0, HarnessX's +14.5%, HarnessForge's +12.0%) are **contested** by Wang et
al. — [[harness-evolution]] holds both sides, and no line below states those numbers without the dispute
attached. (2) **A five-position dispute opened over whether code review scales** — accept the debt,
relocate what review is for, triage by uncertainty, automate the gate, or distribute the reading — see
[[verification-burden]]. (3) **The substrate thread grew an argument with itself**, over whether the
entity has any place in software ([[entity-centric-thinking]]) and over what a DCB "tag" is (three
incompatible statuses). (4) **The SDD critique cluster is now held first-hand** rather than through one
relay — which also corrected the KB's misfiling of [[gojko-adzic]] as a hostile anti-SDD voice: he is not
one, and his "revenge of waterfall" line is a title posed as a question.

Most of this KB is built from practitioner primaries, so **interested-claim markers travel inline on the
entries below** — VENDOR SELF-REPORT, NOT INDEPENDENT, PREPRINT, IMPRESSION NOT MEASUREMENT — for the
reason [[highsmith-practitioner-voice]] articulates: a caveat that lives only on a source page does not
survive being quoted.

## Concepts

- [[llm-wiki]] — pattern where an LLM compiles raw sources into a persistent, compounding wiki
- [[append-and-review-note]] — single plain-text note; append to top, let old notes sink, review
- [[retrieval-augmented-generation]] — retrieve-at-query-time approach the LLM Wiki contrasts with
- [[memex]] — Vannevar Bush's 1945 curated knowledge store; spiritual predecessor of the LLM Wiki
- [[event-modeling]] — design systems as a timeline of events; 3 blocks, 4 patterns, 7-step workshop
- [[event-sourcing]] — store state as an append-only log of immutable events ("no erasers")
- [[event-storming]] — Brandolini's sticky-note domain workshop; Event Modeling's origin
- [[cqrs]] — separate write (commands) from read (views); the basis of Event Modeling's building blocks
- [[agentic-ai]] — goal-seeking, autonomous LLM systems; nondeterministic, inherently distributed (hub page)
- [[domain-driven-design]] — match code to the business domain; shown in Event Modeling via swimlanes
- [[agent-vs-workflow]] — Anthropic's distinction: predefined code paths vs LLM-directed processes
- [[augmented-llm]] — the building block: an LLM with retrieval, tools, and memory
- [[agentic-workflow-patterns]] — five composable patterns: chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer
- [[multi-agent-orchestration]] — specialized agents coordinating; MCP (vertical) + A2A (horizontal)
- [[model-context-protocol]] — Anthropic's standard for connecting agents to tools/data (agent→system)
- [[agent2agent-protocol]] — Google's protocol for agent→agent delegation (agent→agent)
- [[agentic-coding]] — most-used daily agent type; verifiable via tests; Claude Code, Cursor, Copilot
- [[customer-support-agents]] — most common production use case; conversation + tool-driven action
- [[agentic-commerce]] — agents that compare, decide, and buy on a user's behalf
- [[agent-engineering]] — discipline of iterating nondeterministic LLMs into reliable systems
- [[agent-observability-and-evals]] — tracing + offline/online evals; quality is the #1 production blocker
- [[agent-governance]] — decision boundaries, monitoring, audit trails; only ~21% mature
- [[guardian-agents]] — agents that monitor other agents for compliance, safety, drift
- [[agentwashing]] — marketing assistants as agents; explains the adoption-vs-production gap
- [[autonomy-ladder]] — chain → workflow → partially → fully autonomous; most deployments at L1–2
- [[token-budget-quality-cliff]] — output quality degrades with remaining budget, not task difficulty; the model takes shortcuts to "deliver at least something"; silent, ~1-in-5 (focus area)
- [[slice]] — the Event Modeling unit — one step of a business process with its GWT, existing before code; **distinct from [[vertical-slice-architecture]]**, and the unit every agent claim in the KB actually rests on (focus area)
- [[triplet-architecture]] — Dilger's packaging — Event Modeling (plan) + vertical slices (structure) + event sourcing (store) used *in union*; the structural precondition under the agent harness (focus area)
- [[adr]] — one markdown file per design decision, with its options and reasoning; distinct from [[decision-trace]] (human, before the fact vs agent, during the run)
- [[event-sourced-agentic-patterns]] — synthesis: Anthropic's patterns mapped onto the event-sourcing backbone
- [[event-modeled-agent-design]] — synthesis: Event Modeling as a design method for agent/multi-agent systems (focus area)
- [[harness-engineering]] — hub: building/improving the agent harness; failure → permanent fix
- [[agent-harness]] — Agent = Model + Harness; primitives, architecture patterns, vs framework/orchestrator
- [[harness-evolution]] — automatic improvement of the harness by an agent, base model usually frozen: four competing methods, a purpose-built benchmark, two organising surveys — **and a live dispute about whether any of the reported gains are real**. Every source is an arXiv preprint, the critique included. **This is the page that holds both sides of the AHE 69.7→77.0, HarnessX +14.5% and HarnessForge +12.0% numbers; cite none of them without it** (focus)
- [[harness-absorption]] — harness capabilities migrating into model weights, after which the harness deletes the scaffold: train → absorb → shed → repeat, with the inverted metric "progress = how much harness you get to delete at equal capability"; carries the counter-claim at equal weight (Chase: better models *expand* what harnesses must do), and the residue that cannot be absorbed — permissions, identity, trust, legibility (contested; every supporting number is a vendor self-report or secondhand) (focus)
- [[attention-interface]] — the second half of the absorption thesis: once the computer-facing harness is absorbed, the harness **inverts** into a surface aimed at scarce human attention — with a falsifiable, dated prediction (a "human attention policy surface" as universal as AGENTS.md within a year of 2026-08-22, checkable ~2027-08) and no evidence behind it yet (focus)

- [[agent-legibility]] — optimise the repo for the agent's understanding; "what it can't see doesn't exist"

- [[ralph-loop]] — hook that reinjects the prompt in a clean context window to continue work
- [[unattended-coding-agents]] — agents that run with no human in the loop until a PR is ready (Stripe minions; Hashimoto's background agents)
- [[claude-agent-sdk]] — Anthropic's general-purpose agent harness; foundation beneath Claude Code

- [[conways-law]] — systems mirror team communication structure; applied as swimlanes in Event Modeling
- [[react-loop]] — reason → act → observe loop that drives an agent's per-step tool use
- [[prompt-injection]] — untrusted input overriding an app's own prompt (term coined by Willison); the "lethal trifecta"; the safety ceiling on agent autonomy (focus)

- [[mutation-testing]] — measures test-suite *effectiveness* (surviving mutants); the sensor that catches the coverage illusion
- [[spec-driven-development]] — produce a clear spec before code; in the agent era, the spec is the environment that constrains the agent (focus area)
- [[domain-discovery]] — the "understand" phase of modeling; now also done by agents walking a product's live UI (focus area)
- [[dynamic-consistency-boundaries]] — DCB: per-decision runtime consistency scope (optimistic lock) replacing the fixed aggregate; Pellegrini origin (focus substrate)
- [[vertical-slice-architecture]] — VSA: organize code by feature slice not layer; couple in a slice; CQRS out of the gate; maps to Event Modeling slices (focus substrate)
- [[business-capabilities]] — what an org does (stable "what" not "how"); capability swimlanes as long-term-stable boundaries; coupling/cohesion unit; agent ownership boundary (focus area)
- [[wardley-mapping]] — Simon Wardley's strategy maps (value chain × evolution); pairs with capabilities + Event Modeling (where-to-go vs what-to-build) (focus area)
- [[autonomous-domain-capabilities]] — Fritzsche's CCC/RPU: a capability owns its processing, building local context from recorded events instead of a shared object model (focus area)
- [[locality-of-reference]] — keep everything a feature needs in one place so the agent loads only what's relevant; the "codebase is the prompt" principle behind VSA-for-AI (focus substrate)
- [[balanced-coupling]] — Khononov's model: judge coupling by strength × distance × volatility; modularity = localized change + predictable effect; the theory spine under business-capabilities (focus substrate)
- [[coupling-taxonomy]] — the coupling landscape: classical Stevens/Myers/Constantine 1974 vs Khononov 2024 vs Team Topologies vs change-coupling; which fits a capability-graph edge (focus substrate)
- [[team-topologies]] — Skelton & Pais: interaction modes, cognitive load, ISH; partition-side constraints on boundaries, not edge weights (focus substrate)
- [[ai-readable-code]] — code optimized for agents to read/reason/modify; the design side of agent-legibility; converges CLEAR + Balanced Coupling + locality + legibility (focus)
- [[given-when-then]] — GWT: one BDD scenario per command/view, expressed in events; falls out of an event model; the agent acceptance-gate seam (focus area)
- [[screens-as-specification]] — in an agent-facing spec the **screen is first-class content, not derived output**, so screens carry the interaction and GWT carries the rules; the method already had room for it (Event Modeling has always put wireframes in swimlanes), and its worked instance is the filtering chapter where the mockup is readable by the connected agent — **VENDOR SELF-REPORT throughout** (every mechanism is Dilger's own platform, and the fullest primary is an uncaptured webinar); it answers the sceptics' "nobody will open the artifact" objection and explicitly does **not** answer "nobody else signed it": the KB holds no source measuring non-developer participation in a model that later drove agents (focus area)
- [[event-versioning-and-upcasting]] — handling schema change over an immutable event log; upcasting vs. versioned events; the "avoid upcasters" vs "build them in early" debate (focus substrate)
- [[vibe-modeling]] — the Event Modeling answer to "vibe coding": model the system with stakeholders + AI so loosely-prompted code has a structural guardrail; worked instance = Dilger flea-market (non-technical stakeholder co-models by drawing screens) (focus area)
- [[agent-explainability]] — reconstructing *why* an agent decided; framed as an infrastructure (event-store) problem, not a model problem; EU AI Act / SR 11-7 / GDPR (focus area)
- [[loop-engineering]] — the layer one floor above the harness: design the system that prompts/verifies/stops the agent; stacked loops (agent→verification→event-driven→hill-climbing); five primitives + memory; "stay the engineer" (focus)
- [[software-factory]] — the top rung: many harnessed loops fed by a queue, drained through a review gate; "an org chart made of loops"; light vs dark; back pressure (verification is the constraint); loops-vs-graphs (focus)
- [[comprehension-debt]] — the widening gap between how much code exists and how much any human still understands; a dark factory takes it on "with the tests green"; the comprehension side of ai-readable-code / "stay the engineer" (focus)
- [[verification-burden]] — **a live dispute, not a settled position**: agents made producing code cheap and left the cost of *believing* it where it was, and five practitioner answers arrived between May and September 2026 from authors who do not cite each other — accept the debt (Brewster), relocate what review is for and review by exception (Laycock), triage by task uncertainty and enforce what you don't inspect (Tornhill), automate the gate (Osmani), distribute the reading across a team (Willison) — plus Tune's dissent that the loss happens upstream in the modelling and review never carried that function; the shared pivot is *verification ≠ review*, the page states where the positions actually agree, and **nothing here is resolved: the quantity nobody reports is the intervention rate** (focus)
- [[attention-bottleneck]] — three independent authors state the same premise within six weeks (Laycock: "it changed what's scarce"; Willison: "cognitive capacity"; Tornhill: "the parallelisation of human attention that does not scale") and then split three ways on the remedy — widen the span, distribute it, or narrow it; carries Tornhill's mechanism (decision *density*, self-interruption, "3–4 things") and the felt-vs-measured 20%-estimated / 19%-slower gap, **which must be cited only as an unnamed controlled trial as relayed by Tornhill and never attributed to any named study or lab** (focus)
- [[process-managers-and-todo-lists]] — long-running-workflow design: a projected to-do list + focused single-responsibility processors instead of one giant saga/process manager; the worked realization of EM's Automation pattern; "sagas → to-do lists" (focus substrate)
- [[graph-engineering]] — macro orchestration above the loop: directed agentic graphs (nodes = agent invocations w/ per-node tools/model/access; edges return control); loops(micro) vs graphs(macro); Lowin/Prefect, Steinberger spark (focus)
- [[agent-coordination-substrates]] — what many agents actually coordinate *through*, as distinct from how they are decomposed: four structurally different substrates now in the KB (shared task list, blackboard/tuple space, directed agentic graph, append-only event log — the fourth being the *designed* version of the second), **and nobody has compared them**; states the trade-off no source acknowledges, partition-by-ownership versus share-everything, where sharing buys knowledge transfer and has a named capacity cost (the blackboard died to a CI budget) (focus)
- [[em-standardization-foundation]] — "too many islands, too few bridges": the ES/CQRS/DDD field's fragmentation (methodology/vocabulary/examples/tooling) + "The Munich Event" flip-chart proposal for a neutral standards foundation (focus area)
- [[command-context-consistency]] — CCC: record a command's outcome only while the facts its decision read still hold; store-agnostic principle (Westphal/Fritzsche); DCB is its tag-based event-store form; the aggregate is the "Static Consistency Boundary" it retires (focus substrate)
- [[entity-centric-thinking]] — organising a system around the things that change rather than around what happens in the business: Fritzsche's four-capture claim that this habit, not layering or the wrong framework, is the root defect other architectural moves fail to fix — the row is only the residue of the last write, audit and history tables are workarounds for what it destroys, and **VSA improves locality after a boundary is chosen without discovering it**; carries the counter-position on purpose, since Dudycz keeps business logic per entity/aggregate deliberately so slices don't each invent their own notion of an order — **a real disagreement between two practitioner primaries, neither measured, held rather than resolved** (focus substrate)
- [[internal-vs-external-events]] — the events a module *records* and the messages it *publishes* are different populations with different design rules: internal/private/domain versus external/public/integration, plus the reminder that messages are not only events (commands are directed and rejectable; state sync is legitimate if you name it honestly) — and the coinage worth keeping, **"Poor Man's replication through the queue"** for `SthSthCreated/Updated/Deleted` broadcast as if they were events; constrains the KB's agent-EDA thread by saying what inter-agent events must *not* be (focus substrate)
- [[event-modeling-anti-patterns]] — Dilger's "The Shapes": recurring EM *mis*-shapes read off a board's silhouette (bed = the only hard red flag); built to be agent-operable (`/wdyt` skill + reference-catalog linter); agent-as-model-reviewer, upstream of the GWT code gate (focus area)
- [[decision-trace]] — Ng's counter-proposal to the up-front spec: meeting → structured notes → ticket → prompt → in-flight decision log; accumulates during the work instead of describing it beforehand, so a stale spec fails legibly instead of silently (focus area)
