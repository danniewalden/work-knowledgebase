Trust needs to be engineered ( more than ever with AI )

"We are completely driving our boards using AI and MCP." Someone said that to me yesterday. A little later after fixing a problem for them with Claude running into limits: "Thanks, works. I'm already building the slices."
And I know this person is not an engineer, probably never wrote a line of code before. I love it!

They're modeling their complete requirements with AI, and generating working code straight from it. That's was the vision from from the start.

And every engineer thinking now: that´s just vibe coding, good luck in production.
And to be fair, they're not wrong to think it. Code generated by an agent left to its own devices is often crap. Do it long enough and that´s almost inevitable, I´d say.

So how can we do better?

We don´t let the agent freely structuring the system. It's working on a well-defined blueprint architecture. The structure is fully defined upfront, through the event model, slicing, before a single line of code gets written.

All important decisions have been made. The Agent is filling in the blanks, doing the boring typing, faster than any human ever could.

Without that blueprint, the agent decides ( or guesses? ) what's best. To be fair, it's usually pretty good at guessing. But it doesn't need to be wrong often to be desastrous.

One tiny dependency in the wrong place, a little too much coupling in another, and that's the start of a downward spiral in quality that is hard to stop.

So you end up reviewing every single change, because you have no other way to know.
AI can write good code. The thing is, you just can´t trust it to do so reliably.
The real issue is trust.

But doing all those reviews doesn't scale, and to be honest, who wants to review AI generated code anyways? I personally hate it.

Modeling upfront, making the important decisions, defining the structure before anything gets built, that's not bureaucracy. It's engineering trust.

We engineer the system so we can trust what is built, no matter by whom. That's how you work around the review bottleneck. Not by doing more reviews, but by making most of them obsolete.

Which brings me back to that person, building working slices. That only works because the trust was engineered into the system before they ever touched it. That's the actual proof this works. Not a benchmark, not a demo. A non-developer shipping something real.

Trust needs to be engineered. Now more than ever.
