It seems to me like the entire .NET scene has been stuck somewhere in the mid-2000s. Right here on LinkedIn, in particular, there seems to be a bubble that mainly revolves around trivial implementation tips - the kind that Claude Code or Codex can answer in milliseconds. Viewed objectively, these optimization tips don't matter for most applications anyway, because the product is still light-years away from needing to scale.

Haven't you realized yet that this is no longer relevant in the age of AI agents?
And certainly not when your posts are AI-generated anyway.

Writing code is tedious work. And as a passionate programmer with over 30 years of experience, I don't want to downplay that. But programming isn't the most important thing - or rather, writing code isn't crucial for creating a usable application with business value. In the future, we won't need pure programmers who just type code anymore. And I think it's great that this bottleneck is disappearing.

What will matter most is engineering knowledge: How do I design and build a system? How do I handle dependencies? How is the code organized so that I can expand the system without risks? Which patterns are appropriate?

It will no longer be about a specific programming language, but about choosing the right one for the problem at hand. The details within a language will become increasingly insignificant.
